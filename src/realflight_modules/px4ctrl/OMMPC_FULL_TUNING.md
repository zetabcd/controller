### 如何换轨迹

- **保持八字、改大小或速度**：改 `trajectory.figure_eight.length/width/speed/turns/ramp_duration`。本轮只验证上面的规格，尺寸或速度改变后要复测，不要用放宽执行器限制掩盖参考不可行。
- **切回竖直圆翻转**：整套加载 `config/params_ommpc_flip.yaml`，其默认类型已是 `vertical_circle`。
- **切回螺旋翻转**：使用同一翻转文件，并把该文件的 `trajectory.type` 改为 `helix`。调整螺旋形状时使用 `trajectory.helix.*`。
- **只改 `trajectory.type` 不会自动切 PID、前馈或 MPC 模型**。若手动切配置，必须将上表 P/D/F/角速度时间常数成组修改；I、推力模型、权重、频率以及机体/电机参数无需仅因轨迹名称变化而修改。
- 外环类型不是轨迹类型：以上都保持 `PX4CTRL_PRIMARY_CONTROLLER=1`。改编译开关需要重编译；改 YAML 只需重启两个控制节点。

从项目根目录执行，MuJoCo 仍可另开终端启动；两种控制配置二选一：

```bash
source install/setup.bash
# 八字：使用当前默认 params.yaml
ros2 launch px4ctrl run_ctrl.launch.py use_sim_time:=true

# 翻转：完整恢复原参数，默认竖直圆；飞螺旋先改备份文件的 type
ros2 launch px4ctrl run_ctrl.launch.py use_sim_time:=true \
  params_file:="$PWD/src/realflight_modules/px4ctrl/config/params_ommpc_flip.yaml"
```

另开已加载工作区的终端，使用 `ros2 launch quadsim_mujoco mujoco.launch.py` 启动仿真。避免重复启动控制节点。配置通过启动时参数服务传到内环，修改 YAML 后两个节点都要重启。

已重新编译并通过 OMMPC、轨迹、参考、控制接口四组测试。数据目录的 `validation_summary.json`、`validation.png` 和 `all_metrics.json` 保存对照；`before.yaml` 为本轮原件。另有两次启动失败（环境未加载、实验 YAML 整数/浮点类型不匹配）保留日志，因未进入飞行而未计入 17 次有效仿真，不是剔除失飞数据。

| 预测时域 | 16 步 × 0.03 s | 16 步 × 0.03 s |

本轮改善主要来自内环阻尼、前馈与预测模型的匹配。忽略电机动态、TVR 估计误差，将积分项视作扰动时，内环满足：

```text
(1 + D) * omega_dot = P * (omega_cmd - omega) + integral + F * alpha_ref
F = 1 + D, tau = (1 + D) / P
=> omega_dot ≈ (omega_cmd - omega) / tau + alpha_ref
```

因此，提高 D 后不能只按 `1/P` 设置时间常数、同时维持前馈系数为 1。上述关系是近似匹配的起点，实际电机、过滤和通信动态仍由闭环测试检验，不是完整系统辨识。

D 使用已有 TVR 角加速度估计。`filter.lpf_gyro_*` 仅用于监视，不是实际反馈滤波器，修改这些截止频率不会直接改变当前控制律。

新增 `gain.gain_rate_ff_x/y/z`，缺省为 1，启动时读取并检查为有限非负数。内环 `/debugPx4/ratectrl.rate_dot_ref` 记录实际施加的前馈项，使 `P+I+D+FF=alpha_cmd` 仍成立；原始参考仍可从 `/rates_thrust_setpoint.rate_dot_ref` 查看。

内环参数由各外环共用。本次仅验证 OMMPC；切换 acados 或其他外环后需要重新匹配其模型，本轮没有改写用户的 NMPC 配置。

## 其他筛选结论

- 只将内环 P 加倍、保留旧模型（`p20_oldtau42`），全动作误差为 6.27 cm；同步调整模型的 `p2042` 为 0.88 cm。
- P 提高至 4.5 / 6 倍、P 三倍且去掉 I、P 三倍且大幅降低输入/平滑惩罚，均在初筛失飞。
- P 三倍的单次好成绩未通过全部复测，最终采用较适中的 P。
- 200 Hz 外环、加密预测网格、收紧 QP 容差和更高位置权重没有成为最终推荐。参数有耦合，不能据此概括某一参数永远越大或越小越好。
